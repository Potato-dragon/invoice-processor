# Handoff A2: Backend skeleton, database, queue, stub pipeline

**Branch:** `lane-a/skeleton`
**You own:** `docker-compose.yml`, `.env.example`, `backend/` (everything except `backend/app/parsing/`, `backend/app/extraction/`, `backend/app/validation/`, `backend/tests/eval/`), `backend/Dockerfile`, `README.md` (run instructions only).
**Do not touch:** `frontend/`, `tools/`, `data/`, `docs/CONTRACTS.md`.
**Read first:** AGENTS.md, docs/ARCHITECTURE.md, docs/CONTRACTS.md.

## Goal
A running system where uploading a file through the API creates a document, runs it through all four stages using STUB stage logic, updates statuses and writes processing events. Real parsing/extraction/validation will be plugged in later by other lanes, so the interfaces must match CONTRACTS section 8 exactly.
6. **Upload endpoint** `POST /api/documents` (multiple files). Per file: detect type by magic bytes (PDF, JPG, PNG, TIFF, XLSX, XLS, CSV), enforce `MAX_UPLOAD_MB`, reject unsupported/empty files with the coded error, compute sha256, store, create row, enqueue `parse`. One bad file must not fail the batch.
7. **Read endpoints**: `GET /documents`, `GET /documents/{id}`, `GET /documents/{id}/events`, `GET /documents/{id}/file`, `GET /invoices/{id}`, `GET /stats`, `GET /health`. Pagination shape per CONTRACTS section 9. Search, PATCH invoice, crosschecks, reprocess: return 501 with a coded error for now except `reprocess` (see 9).
8. **Auth + limits**: `X-API-Key` check on everything except health; basic rate limiting on upload (e.g. slowapi); API error body per CONTRACTS section 4 on every error path including validation errors and 404.
9. **Pipeline runner + stubs**: a stage runner that, for each stage, writes a STARTED event, calls the stage function, writes SUCCEEDED/FAILED with duration, updates `documents.status`/`current_stage`, and enqueues the next stage. Stage functions are imported from the real lane packages if present, else from `backend/app/stubs/` (stubs return plausible fake data matching the contracts: 1 page, 1 invoice, fake extraction, no issues). Stages must be idempotent (re-running never duplicates rows) and use retry with backoff for transient errors; `PipelineError` fails the document immediately with its code. Implement `POST /documents/{id}/reprocess` to resume from the failed stage.
10. **Tests** (pytest, run inside the container or against compose): upload happy path reaches COMPLETED with 4 SUCCEEDED events; unsupported type returns FILE_TYPE_UNSUPPORTED; empty file returns FILE_EMPTY; oversize returns FILE_TOO_LARGE; missing API key returns UNAUTHORIZED; a stage that raises `PipelineError("OCR_FAILED", ...)` leaves status FAILED with that code; reprocess after fixing the stub completes; re-running a stage does not duplicate rows.
11. **README.md**: how to start from a fresh clone using PowerShell (`docker compose up --build`), how to call the API with curl or PowerShell `Invoke-RestMethod`, how to run tests. Keep it short.

## Acceptance checks
- `docker compose up --build` starts all four services with no manual steps; `GET /api/health` returns ok.
- Uploading a small PDF and a CSV via the API ends in status COMPLETED with processing events for all four stages.
- All tests in task 10 pass.
- Alembic migration applies on an empty database and matches CONTRACTS section 6 (every table and column present).
- No dependency over ~100 MB; image builds on a laptop with limited disk.

## Out of scope
Real OCR, parsing, extraction, validation, search logic, frontend.
