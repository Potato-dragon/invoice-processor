# Handoff A1: Backend skeleton, database, queue, stub pipeline

**Branch:** `lane-a/skeleton`
**You own:** `docker-compose.yml`, `.env.example`, `backend/` (everything except `backend/app/parsing/`, `backend/app/extraction/`, `backend/app/validation/`, `backend/tests/eval/`), `backend/Dockerfile`, `README.md` (run instructions only).
**Do not touch:** `frontend/`, `tools/`, `data/`, `docs/CONTRACTS.md`.
**Read first:** AGENTS.md, docs/ARCHITECTURE.md, docs/CONTRACTS.md.

## Goal
A running system where uploading a file through the API creates a document, runs it through all four stages using STUB stage logic, updates statuses and writes processing events. Real parsing/extraction/validation will be plugged in later by other lanes, so the interfaces must match CONTRACTS section 8 exactly.

## Tasks
1. **docker-compose.yml** with services: `db` (image `pgvector/pgvector:pg16`, volume), `redis` (redis:7), `api` (FastAPI, port 8000), `worker` (RQ worker listening on queues `parse, extract, validate, index`). Backend image based on `python:3.12-slim` plus `tesseract-ocr` (and English language data) and `libgl`-free OpenCV (`opencv-python-headless`). Named volume for `/data/storage`. Healthchecks on db and redis; api/worker wait for them.
2. **Config** from env vars per CONTRACTS section 2, with `.env.example`.
3. **Database**: SQLAlchemy models and an Alembic migration creating every table in CONTRACTS section 6 (enable the `vector` extension; include indexes). Migration runs automatically on api start.
4. **`backend/app/contracts.py`**: Pydantic models and `PipelineError(code, message)` implementing CONTRACTS sections 3, 4, 5, 7, 8 (enums, error codes, issue codes, ExtractionResult, ParsedDocument, ParsedPage, LedgerRow, IssueModel, CrosscheckResult). Keep it importable with no heavy deps.
5. **Storage interface** (`Storage` with `save`, `open`, `delete`) with a local-volume 
implementation. Generated storage keys only; never use the client filename in a path.
## Acceptance checks
- `docker compose up --build` starts all four services with no manual steps; `GET /api/health` returns ok.
- Uploading a small PDF and a CSV via the API ends in status COMPLETED with processing events for all four stages.
- All tests in task 10 pass.
- Alembic migration applies on an empty database and matches CONTRACTS section 6 (every table and column present).
- No dependency over ~100 MB; image builds on a laptop with limited disk.

## Out of scope
Real OCR, parsing, extraction, validation, search logic, frontend.
